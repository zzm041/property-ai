# 客户文件扫描服务

客户 overlay 包含固定摘要的 ClamAV 1.4.6 服务。它只加入独立 Docker 网络，不向宿主机发布端口；API、Worker、Publisher、Beat 同时加入该网络。数据库、对象存储、模型端口和扫描端口均不可作为公网入口。

## 启动与配置

1. 检查主机局域网、VPN 和 Docker 已用网段。模板 `CUSTOMER_SCANNER_SUBNET=172.31.240.0/28` 与 `FILE_SCANNER_HOST=172.31.240.2` 是可修改的成对配置，不能与现有路由冲突。扫描地址必须是该网段中可用的内网数字 IP；不使用 DNS 别名。
2. 生成应用配置后，使用客户 Compose 组合执行 `up -d scanner`。该动作只适用于获批准的新客户项目；不要把客户 overlay 套在现有本地交付项目上。
3. 等待 `scanner` 健康后再启动应用。应用启动依赖扫描健康；运行中扫描超时、故障或返回不完整结果时，上传附件保留待检状态，不作为安全附件对外展示。
4. 运维执行同一 Compose 组合的 `exec scanner clamdscan --version` 核对引擎和病毒库日期，查看 `logs --tail 100 scanner` 确认 FreshClam 更新成功。引擎健康并不证明病毒库足够新，网络隔离的甲方必须建立离线病毒库更新流程。

扫描进程内存上限为 4 GiB、CPU 上限 1 核；这部分资源应单独计入整机预算。关闭并行病毒库重载以降低更新时内存峰值，更新期间扫描可能等待，应用仍按超时保留待检。上传和流扫描上限均为 10 MiB，解包扫描总量上限为 40 MiB；不要只修改应用上传上限。

`scanner_data` 是客户项目独立的病毒库持久卷。正常部署启用 FreshClam，保留病毒库以避免每次重建重复下载；需允许其访问官方更新网络。不要用 `down -v` 清理日常服务，也不要向此卷写入用户上传内容。

## 已验证边界

2026-11-08 在独立临时容器中验证：正常合成文本为 clean，内存中构造的官方 EICAR 无害测试样本为 blocked，应用超限、引擎流超限和服务停止均为 pending。引擎版本 1.4.6，镜像预装病毒库版本 28171（2026-11-01）。临时容器已移除，无模型或真实用户文件调用。

此隔离检查为避免额外下载关闭了更新程序，因此不能证明甲方网络能更新病毒库；正常客户配置启用更新。最终净包全栈验证和实际部署的病毒库更新核对仍须完成。
