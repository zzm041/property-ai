让每一次报修，
都有清晰的处理路径。

住户用文字、图片或语音描述问题，AI 整理报修信息，系统按服务范围与人员条件派单。维修人员处理、主管跟进异常、住户查看回执，在同一条工单中完成协作。

从一个报修开始流程示意
“厨房的灯打开以后不亮，请安排维修。”
  1. 1
    识别诉求

    整理设备、故障现象、位置与联系要求；信息不足时请求补充。

  2. 2
    匹配人员

    按小区、职责、签到、技能与工作容量筛选，再执行派单规则。

  3. 3
    跟进结果

    记录处理过程与前后照片，向住户提供回执并接收确认。

无法处理的情况由维修人员上报，物业主管继续协调。

一张工单，连接三个角色

从住户提交，到处理结果确认。

住户：描述问题，查看进度

提交文字、图片和语音报修，补充现场信息；查看处理回执、前后照片与费用说明，确认解决或继续反馈。

维修人员：接单，处理，回执

签到后接收符合职责的工单，记录到场与处理情况。遇到无法解决的问题，通过独立异常页面提交原因。

物业主管：调度与异常跟进

查看待派和异常工单，核对诊断依据，进行人工派单、改派或协调；持续保留工单状态与处理记录。

AI 参与业务的具体环节

理解报修、查找知识、辅助主管决策。

报修理解

把零散描述整理成可处理的信息

文字、图片与语音进入统一分析流程，提取问题事实、职责、风险和待澄清事项。结构化结果经过校验，供工单展示与规则调度使用。

规则派单

结合实际服务条件安排人员

业务服务校验人员所属小区、有效服务关系、签到、职责、技能与容量，再按派单政策选择人员。AI 提供问题信息，人员选择由业务规则执行。

知识问答

从有权限的物业知识中查找依据

检索与重排结合，回答带引用来源。知识按租户、小区和可见性过滤，访问时检查权限与文档版本。

主管 Agent

读取队列与诊断，生成有依据的跟进建议

通过“查询队列 → 读取工单诊断 → 汇总建议”的受限工具循环辅助主管核实工单。每次读取重新鉴权，建议引用已读取的业务事实，派单和状态变更仍由主管操作。

可选功能，默认关闭；启用前需配置独立模型服务与权限。

模块化单体与异步处理

业务记录先保存，AI 分析异步执行。

微信原生小程序住户 · 员工 · 物业主管
→
FastAPI 业务服务身份权限 · 工单状态 · 规则派单
→
Celery Worker报修分析 · 知识处理 · 重试

MySQL 保存业务数据，Redis 提供缓存与锁，RabbitMQ 承载异步任务，Milvus 支持知识检索。Qwen 系列模型与语音、向量和重排服务通过 Provider 接入，Docker Compose 与 Nginx 负责部署。

异常仍可继续处理

模型超时或分析失败时保留原工单。异步任务记录投递、重试与失败状态，物业可通过人工队列继续跟进。

数据按角色隔离

租户、小区和资源所有权共同约束访问。住户回执与内部处理记录分别展示，附件访问重新检查权限。

状态变化可追溯

工单流转记录业务日志，管理与安全操作写入审计日志。后续补充、异常协调和多轮处理保留上下文。
