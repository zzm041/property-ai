# 07 — 安全与隐私

## 1. 威胁模型（V1 必须防）

- 越权访问其他小区工单 / 住户手机号
- 验证码被刷导致短信轰炸
- 弱口令与撞库
- 上传恶意文件
- 日志泄漏身份证、验证码、Token
- 知识库跨小区召回
- 账号抢绑（用别人手机号、别人微信）
- 派单接口被普通员工改派给自己刷单

## 2. 身份安全

- 密码：强哈希（Argon2id 优先，bcrypt 可作兼容）。禁止明文、禁止可逆加密。
- 验证码：只存哈希、短 TTL、尝试次数上限、图形/行为频控 + 每号每小时上限。
- 登录失败锁定：按手机号 + IP 双维度。
- Token：短效 access + 可旋转 refresh；登出作废。
- 换手机 / 换微信 / 合并 / 恢复：二次验证 + AuditLog。
- 高风险恢复：第三方实名 + 活体。本系统 **禁止** 存原始人脸图用于比对，禁止自建人脸特征库。若 Provider 回传照片，只作审核工单的短期对象存储并设 TTL，不进入向量库。

## 3. 数据分级与脱敏

| 级别 | 例子 | 存储 | 日志 |
| --- | --- | --- | --- |
| L1 公开 | 小区名、已发布公告 | 明文 | 明文 |
| L2 内部 | 工单摘要、员工姓名 | 明文 | 明文 |
| L3 个人 | 手机号、房号+姓名 | 明文+访问控制 | 脱敏 `138****1234` |
| L4 敏感 | 身份证号 | 字段加密 | 禁止 |
| L5 禁止落库 | 人脸特征、验证码明文、密码明文 | 不存 | 不存 |

管理后台默认展示脱敏值，显式“查看明文”再记审计。

## 4. 租户隔离

- 每个查询在 repository 层强制 `tenant_id`（及需要时 `property_id`）。
- 禁止把隔离过滤只写在前端。
- 系统管理员默认看元数据；看业务明文需单独权限。

## 5. 文件上传

- 类型白名单、大小、魔数、随机存储名、不可执行目录。
- 访问通过鉴权 URL 或带过期签名，不暴露可枚举的连续 ID 文件路径。

## 6. 密钥管理

- 所有 Secret 来自环境变量或部署侧 secret 文件。
- `.env` 不入库。`.env.example` 只有空值和假数据。
- 不同环境不同 `APP_SECRET_KEY`。

## 7. 并发与幂等

- 创建工单、发送短信、接单、发布公告、账号合并必须幂等或条件更新。
- 使用 `Idempotency-Key` 表防重复提交。
- 派单容量用 Redis 锁 + DB 校验，避免超卖负载。

## 8. 合规注意（实现约束）

- 人脸与身份证核验走具备资质的第三方 Provider（生产）。
- 开发环境永远走 Development Provider。
- 备份文件与数据库转储按敏感级加密；恢复演练不使用真实业主全量拷到个人电脑。

## 9. 安全开发检查（每个模块）

- [ ] 未授权 / 错误范围返回 401/403
- [ ] 跨小区 IDOR 测试
- [ ] 错误信息无栈、无 SQL
- [ ] 速率限制
- [ ] 审计字段齐全
