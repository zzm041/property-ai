# 语义校验下一增量的修正边界

这是基于首轮真实失败制定的实施验收清单，不是新语义协议已上线，也不变更正式业务政策。继续现有 Provider/Service/Worker，不增加框架、基础设施或新的业务录入步骤。

## 必须分开的判断

| 层次 | 当前问题 | 修正约束 |
| --- | --- | --- |
| 来源真实性 | 有正确 evidence_id 不等于所有模型陈述都被支持 | 继续验证当前目录、来源、跨度和输入类型；历史不成为当前证据 |
| 现象理解 | 词表未匹配混同为模型输出错误 | 未匹配原因单独统计；不得逐条补本批样本词汇作为完整解决方案 |
| 事实确定性 | 系统不知道分类，不等于住户没说清现象 | 不把明确事实自动改成“待核实”；确实未知的主体、时间、原因分别保留 |
| 分类覆盖 | 机械关闭、排水缓慢、清洁物和安保观察被硬塞入错误标签 | 以实际可观察现象定义类别边界；正常简单任务不能全部转人工充当成功 |
| 业务控制 | 字段各自合法但互相矛盾，仍可能错误分流 | 先验证跨字段一致性；权限、状态、职责和最终选人始终由服务器控制 |
| 证据展示 | 摘要没重复所有否定背景被误判为遗漏 | 预先区分摘要、结构化字段、联系/上门限制的保留要求，禁止相反推断 |

## 实施顺序

1. 固定旧 12 条原始结果与失败分类，转回归集；明确目前不是独立人工标注，不追改金标让旧模型通过。
2. 先补确定性的字段矛盾和可追踪原因。本轮已修燃气观察与 risk 冲突；模型未识别燃气不在本项覆盖范围。
3. 为新版观察契约定义“语义等价/不等价”的成对案例，再修改类别、提示词和校验。除明确/否定/历史，还要覆盖多主体同句、相邻分句、转述、未知类别、危险事实与注入。
4. 把来源及协议合法性校验和语义判断分开；不得以“来源字符串存在”证明语义正确，不以模型自报置信度代替实测正确率。是否需要额外语义复核调用，应由单轮提取失败分析及预算决定，本轮不新增调用或默认第二模型。
5. 新协议若改变 label/subject/事件键语义，必须同步 schema、Provider canonical schema、提示词版本及缓存键，并验证旧分析读取、同输入复用和事件聚合；不回填历史或将历史事件重新聚合。
6. 真实模型重跑旧样本只算回归；另用预先冻结的新样本验证泛化。通过条件分别检查错误放行、过度拒绝、危险事实、联系限制和任务完成，不只汇报一个综合百分比。

2026-11-05 后续确定性增量：相邻分句有明确竞争主体时，错误绑定不能借另一正确观察降级放行；同标签多个有效匹配优先选取支持声明主体的分句。见 `reports/semantic-subject-20261105/REVIEW.md`。这是既有绑定约束修复，不是上方新版契约与完整类别覆盖已完成。

## 停止与交付门槛

- 不降低来源、越权、否定/历史污染的既有失败测试来追求接受率。
- 明确危险不能因主体未知、住户离开或分类缺口而消失；也不能凭空补造危险事实。
- 正常类别/职责明确的任务必须形成可用结构，不能以统一人工接管替代原目标。
- 方案需经代码与规格复审后实现；若实际涉及正式规格冲突，再只暂停冲突部分。当前这份清单不批准更改 WAIT_CONFIRM 容量、RAG 降级或未知职责人工录入政策。
- 源码、保存输出回放、真实模型、SQL/API、模型与数据库/页面组合验收分别记账。最小可用范围通过后收口，不扩建可选 Agent 场景。
