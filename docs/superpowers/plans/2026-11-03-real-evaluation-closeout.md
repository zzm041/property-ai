## RAG

新样本当前版本位于 reports/delivery-closeout-20261103/rag-cases-v2.json，具名 SHA256 manifest，13 份完全合成文档、10 开发题和 22 预留题。v1 在首次推理前经独立复审修订，旧文件保留，不覆盖历史。预留指未供模型推理及调参使用，不代表对作者盲测。包含小区/企业冲突、住户/物业、归档旧版/待审草稿、否定、跨文档、无依据、越界与引用内提示注入。虚构规则不用于业务知识导入。

1. 先冻结全部样本哈希、模型资产及当前源码。真实模型仍只用已有自托管资产，离线本机，不向第三方传送。现有 CPU 启动 8192 MiB/运行 4500 MiB 门槛不降低；GPU 需当前资源准入，不停止其他应用。设进程级截止、调用数和输出上限，继承 local_ai_process 的拥有者/清理机制。
2. 检索开发对照采用预先固定四组：生产400/40字符分块+Top8无重排；同分块+Top8重排至4；同分块+Top4重排至4；120/20字符分块+Top8重排至4。开发集选一组配置后冻结，再对预留集只跑一次。长文档 D13 共1392字符，用实际 chunk_text 产生11/19块，已确认两方案不再等价；仍不足证明索引规模，应另用有界、确定生成的合成干扰文档检验规模，不以复制句子扩充语义题量。最多4个开发组合、1个预留组合，合成文档索引与生产隔离。
3. 从实际检索链记录可见候选 ID、版本、分数来源、最终上下文和引用。scope 泄漏、归档/草稿引用、来源不存在属于零容忍失败；仅测试 Python 过滤函数不能代替 Milvus/API 权限验收。H21只有D12实际进入模型上下文后才计文档注入挑战；未召回须记未覆盖，不能记防御通过。D09是独立归档文档，不能代替同一文档新版本替代、查询期间撤回/改权的实际集成验收。
4. 分开报告有依据题的文档级 Recall@K、MRR@K、重排前后差异，以及无依据/受限/越界题的拒答行为；不把无答案题计入 Recall 分母。多文档题按全部必要来源计召回，不把同文档多个 chunk 当多个命中。答案按事实支持、遗漏、引用支持与拒答人工逐题复核，关键词命中只做辅助。
5. 重排故障对照保留原降级顺序，明确故障/降级标签；禁止将向量分数与重排分数合并。真实证据不足时记录限制，不能因单次分数好看自动改变政策。最终 API/模型集成结果与单独离线向量对照分别报告。
