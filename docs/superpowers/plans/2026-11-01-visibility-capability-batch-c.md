## C1 视图契约

详情增加 audience=resident/property，默认 resident；这只是请求的输出视图，不是权限事实。所有读取先验证既有资源权限；property 视图还须有目标范围 READ + 管理权限，或有效的当前负责员工身份，不能因报修人也是管理员而在默认住户视图输出内部字段。物业页面显式请求 property；直接伪造参数仍由后端拒绝。

住户输出使用字段白名单：保留工单状态/时间/SLA、所属范围与报修人标识（通知路由依赖）、处理轮次/展示名、明确回执结果/费用/未解决原因/后续安排、本人反馈。去掉内部派单理由/操作者标识、模型执行明细、非业务审计日志。公开状态不能因隐私隐藏成“已解决”。内部混合 extra_notes 不直接输出；从明确来源的住户 APPEND 日志重建其补充，新写入把住户正文保存进既有 WorkOrderLog.payload_json.reason（无迁移）。历史无来源文本不猜测归属，物业保留原文。

居民附件只展示 REPORT 和明确关联既有回执的 BEFORE/AFTER；不直接公开 ON_SITE 内部过程资料。相同判定同时用于响应投影与下载鉴权。原始历史媒体不删除，物业授权视图保留。

## C2 历史文件访问

文件一旦关联工单，不因 uploader_user_id 相同直接放行。逐一核对当前工单权限及 audience 下的媒体可见性；无合法关联返回既有 404，不读取 Storage。尚未关联任何工单的本人上传保留预览能力。跨工单复用时有至少一个合法可见关联才可读；这不是新建永久外链或客户端授权。

## C3 人工职责与技能

复用现有类别/职责、普通维修组及特殊技能规则，不让主管选择绕过限制。先校验已有明确有效分析的职责/技能及明确类别；普通维修标签不变成专属执照，特殊技能必须具备。用户已选择“暂不扩展人工录入，先修正已有明确职责的工单”；未知且无可靠分类保留原人工兜底，不拿低置信/FAILED/STALE 或不同类别的模型字段硬过滤。本批不改容量策略。COMPLETED 但结构非法的要求不静默丢弃限制，拒绝资格校验，需修复分析记录后再处理。
