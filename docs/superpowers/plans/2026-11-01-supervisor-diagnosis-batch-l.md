# T14/T09：主管只读处理诊断

已批准v2首选“为何未派单/多轮处理/超时，下一步做什么”。当前问题可以由一次受控读取回答，因此先落实可用页面和只读工具能力，不引入LLM工具循环、框架、依赖或新服务，不宣称已实现自主Agent。

GET /supervisor/work-orders/{id}/diagnosis?property_id=...&version=...：同现有主管队列的work_order:dispatch目标scope权限，重新加载身份；校验目标property和选中版本，拒绝越权/陈旧页面。读取当前状态/子原因、当前Process轮次、当前analysis状态和最新AUTO_DISPATCH_WAIT日志，来源带实体类型/ID及时间。历史派单尝试必须明确不是当前员工资格。轮次不是返修次数，不能据此归因给员工。只输出固定事实标签及建议，不返回姓名、电话、原始日志/提示词/正文、画像或分数。

状态提示：未分析完成可转人工，待派读取最后等待原因，处理中按等待/升级原因给人工跟进提示；WAIT_CONFIRM提示核实住户反馈，终态不再报现场SLA超时。SLA沿用已有配置与due_at，不硬编码时限。每条建议由主管在现有业务入口决定，诊断不派单、不重分析、不改状态、不commit。

页面新增“查看处理诊断”，绑定所选工单/小区/版本。切换、刷新、隐藏/退出和任何后续业务操作清空诊断；旧异步成功/失败不能覆盖新选择。读取失败显示原因，不展示旧事实。既有“重新分析并查看建议”保持独立，诊断按钮不会触发它。

实施目标：domain/diagnosis.py、schema/work_order.py、WorkOrderService、WorkOrderRepository、supervisor路由、api.js及queue.js/wxml，API说明。纯合成Python测试与Node页面交互；真实运行验收在服务授权部署后进行。无持久表/迁移/模型/GPU/费用，暂缓的容量和反馈统计政策不变。

验收：目标权限、身份撤回、跨小区、版本变化拒绝；无wait日志/未知原因安全提示；历史源ID/时间、过程轮次含义正确；终态SLA不假报；无写操作/模型；页面上下文过期响应拒绝。最终独立只读复审。
