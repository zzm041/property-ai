# S：回执实际处理记录

沿用已批准 T08/T10。按最新连续实施授权执行，保护 R 及既有 WIP；EKB 不修改。不改变容量、确认、评价分母或排序，不新增迁移和审批子系统。

问题：负责人和回执提交人并不能证明实际参与维修。外部人工支援不能自动算成负责员工个人完成。既有历史不推断补填。

最小实现：回执请求可选 handling_mode=SELF/ASSISTED/EXTERNAL、handling_note。默认未记录；协作或外部支援须说明实际参与人员/单位及分工（255字内，不填写电话等私人信息）。模式指提交者对自己参与情况的声明，不是系统核实或绩效评分。SELF/ASSISTED 关联当前提交者的合法员工身份，不能误用被代理工单负责人的身份；EXTERNAL 不生成员工贡献归属。

同一回执事务的已有 WorkOrderLog 保存 receipt_handling_v1（receipt_id/process_id/mode/note/自报参与员工ID）；日志 actor 保留记录人，Process 保留原负责人。回执正常/未解决均覆盖。正文生成内部可读说明供现有员工和主管历史页面读取；住户既有白名单继续排除内部 reason 和结构化字段，必要费用/结果/风险保持原输出。旧客户端不带字段继续工作，无“默认本人完成”。不改旧回执，不重放工单。

范围：独立小型 domain 校验/格式化、StaffReceiptRequest、staff_work_orders 接线、WorkOrderService 回执和日志参数、员工回执表单、正式接口增补、专项 Python/Node 测试与限定复测入口。原生副本不作为产品源码。

验收：先 RED；SELF/ASSISTED/EXTERNAL/旧输入、空白说明、未知模式、过长输入；已解决/未解决都写正确 receipt/process 与记录者；代理提交不能将其自报参与错误归到负责人；既有身份/版本/一次回执约束不放宽；住户看不到内部说明，物业能读；Node 证明默认未知、按需说明和请求字段、重复打开不沿用另一单的参与声明。相邻回归与独立只读复审。结构化履历统计另批，不能由此声称人员画像完成。
