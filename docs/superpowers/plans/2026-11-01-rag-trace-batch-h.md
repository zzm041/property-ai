# T13a 第一子批：RAG 可诊断的请求轨迹

已批准 v2 要求最小结构化轨迹，不新增平台；本批沿用现有 logger。只改 RetrievalService 和合成测试，不改输出、权限、事务、排序、阈值、模型预算、依赖或部署。

每次 query 一条汇总事件：request_id、受限 audience、prompt_version、最终状态、稳定错误码、总耗时、召回/可见/选中/引用数量、是否重排回退、拒绝阶段。每个实际调用的 embed/search/rerank/generate 阶段记录耗时、成功/失败、模型标识与合法 token 数（未知为 null，不推算）；不记录未调用阶段为成功。请求状态和 Provider 状态分开，Provider 成功但输出无效仍应有明确结果原因。鉴权拒绝或非预期异常也能结束轨迹，但原异常仍上抛。

轨迹对象为每次调用局部变量，不能存在 Service 上产生并发串扰。只允许内部固定标签、数值和名义模型版本，不记录 question、prompt、answer、知识内容、源定位、文件/用户身份或 exception message。日志写入故障不得改写业务成功/拒绝结果；不将日志作为法定审计或唯一验收证据。

先测试正常、空召回、低相关、Provider 超时、重排回退、坏输出/引用、权限变化、未知异常、两次调用无累积、日志故障不改变结果。使用现有合成 fixture，不调用模型或数据库。后续任务仍包括工单/任务关联、复用事件、预算与真实容量；本批不关闭整个 T13。
