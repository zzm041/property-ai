# 业务闭环与 AI 技术完善：修订设计 v2

日期：2026-11-01。范围：此前数轮业务、运行、安全、AI/RAG/Agent、岗位技术深度审查的合并，不仅最近一轮。

后续决策记录（2026-11-02）：用户要求先完成物业并通知，再开始企业知识库修改完善；本设计以下EKB冻结指物业实施阶段，后续阶段按最新授权推进并保留原冻结证据。用户暂缓容量/反馈政策，并明确保留现有重排失败降级，待真实评测后决定。最新逐项状态见reports/implementation-status-20261101.md；不将本设计历史处置冒充当前完成度。

## 目标与授权

面向住户和物业两类客户，先确保现实业务成立、流程通顺、异常有人负责、结果可追溯，再以经过验证的技术改善体验与可靠性。初中级 AI 应用/Agent 岗位为主要参照，高级要求仅作进阶目标。

用户已授权：先修订并审查方案，确认后可开始普通源码、测试、页面修正。当前由主会话实施；不提交、不推送、不部署。迁移、真实数据、真实短信/模型调用、GPU、费用、共享服务与正式发布仍单独批准。E:\enterprise-knowledge-base 持续冻结。Codex A/B 职责不变。

本设计不能把未验证风险写成事故，也不能把方案覆盖写成功能完成。批次 A 是可直接执行的有界缺陷修复；其余任务有完整追踪，但不得在详细接口、规格冲突或安全前提未解决时直接实施。

## 已确认的业务取舍

- 保留统一普通维修组、单负责人、不默认拆单；正常且信息充分、存在合格员工的报修继续自动处理。
- 人员能力先记录真实擅长项目、必要资质和履历。先修正反馈口径；不预设复杂等级、认定体系或未经评测的权重，不发布员工排名。
- 跨小区支援采用按需上报、电话/工作群人工协调、授权主管记录安排和结果。能在本小区解决则不逐单上报。紧急情况不等待 AI 或额外审批。
- 本批不建设独立支援审批、定时授权、自动抢占或跨租户调度系统。无合法系统权限的支援人由主管如实记录实际工作；不借账号、不伪造 Assignment，不把支援人的成果自动算给负责人。
- WAIT_CONFIRM 的方向是现场容量与后续责任分离、不超时自动判成功。实际改动需覆盖重开时容量重验、幂等释放、既有回执和事件共享容量。原规格将 WAIT_CONFIRM 计入占用，不能在无专门变更记录的情况下顺带改变。
- 等待配件、住户配合、外部协调等必须有负责人、进展和下一步；不强制把每次沟通变成审批，不让员工凭一个理由擅自解除责任。
- 对客进度与内部记录分开；安全风险、未解决、延误和应告知费用不能以内部保密为由隐藏。
- 技术深度由权限、事务、幂等、恢复、证据约束、评测和可观测性支撑；不强制引入 LangChain、语义缓存、多 Agent 或新基础设施。

## 意图、复用和框架的技术验收口径

- **入口意图**：报修、查进度、知识咨询、其他请求是待核实的入口能力，不能把故障分类等同于完整意图路由。T11 先查现有入口，再定义少量真实业务意图、歧义澄清及越界请求处理；固定页面入口已经明确用途时不额外调用模型猜意图。
- **分析结果复用**：当前 `backend/app/service/analysis.py` 的输入哈希包含提示词版本、工单、文本、ASR、媒体与上下文，并已有 Provider 检查点路径。这只能证明这些机制存在；T06b 仍须验证模型/协议变化、补充/删除媒体、并发重试与旧结果重映射，不能直接宣称完整缓存失效机制已通过。
- **问答/意图缓存**：与上述检查点分开核查。若需要缓存，先使用可解释的精确键，包含授权范围和必要版本；用户/小区/可见性、知识版本改变必须隔离或失效。每次读取仍重验权限，动态工单状态与最终派单资格不得直接复用旧快照。不为岗位关键词引入语义缓存。
- **框架**：当前 `backend/pyproject.toml` 未声明 LangChain/LangGraph；这不等于缺少技术深度。现有 Provider/Service/Worker 优先复用；只有单个业务场景明确需要持久步骤、工具编排且自有实现成本更高时，才比较框架收益。冻结依赖变更仍需单独批准。
- **深度证据**：每个能力应同时展示设计取舍、失败恢复、隔离与幂等、版本可追踪、代表性评测和实际限制。模拟测试、固定样本模型试验、现场业务验收分别记录，不能互相替代。

## Agent 的现实场景与范围

首选场景为主管询问“为什么未派单/重复维修/超时，下一步应该做什么”。只读工具查询授权工单、实际历史、人员资格/容量、SLA、可见 SOP。模型选择查询顺序，但资格与事实来自业务 Service。输出事实、来源、未知项和建议；由人决定并通过现有业务入口操作。不自动派单、关闭、发布或审批。

若一次查询或固定流程足够，先实现该能力，不包装成自主 Agent。确需 Agent 时，详细方案必须明确工具参数/返回 schema、每次鉴权、预算/步数/截止时间、取消/恢复、版本重验和任务级评测；没有详细契约与具名模型预算不启动真实实验。

第二场景为住户本人报修澄清与进度，写操作必须显式确认并重验业务状态。第三场景为物业知识草稿，人工审核发布。它们是可选场景，不是三个协同 Agent。EKB 不参与变更。

## 批次 A：可以安全落地的接口契约

1. 不增加 API、配置、表、依赖或后台服务。继续使用 AssistantAnswer 三种状态。
2. 查询的 embedding/vector 阶段若发生已知 Provider 超时、不可用、限流或非法输出，返回 knowledge_unavailable，不保留模型答案，沿用固定安全提示“知识助手暂时不可用”、空引用，不再调用后续模型。
3. 重排阶段这些错误及长度/数值契约失败均回退到已通过 ACL 的向量召回顺序，最多取既有 Top-K；明确这是未评分的降级，不构造虚假 1.0 分。保留正常路径相关性阈值。这个回退来自既有代码行为，不冒称正式规格已明确相同细节。弱证据门槛仍属 T02c 后续评测。
4. 生成阶段已知 Provider 错误或 schema 错误返回 knowledge_unavailable，使用同一固定安全提示和空引用。模型明确返回 unavailable 时不因没有引用被改成 insufficient。schema 合法的明确 insufficient 返回空答案/引用，丢弃其附带的无用文本或引用，不因未知引用改为服务故障；schema 非法仍按契约错误处理。answered 无引用维持不足证据处理；answered 存在任一未知引用则整条回答拒绝，不截去引用后继续展示。
5. RAG 引用只接受正整数，拒绝布尔值、字符串及非正数；合法重复 ID 可按已有引用列表自然去重。此契约与当前提示词一致。
6. HTTP 重排适配器拒绝非对象根结构、错误长度、布尔/空/非法/非有限分数；已有有限数字字符串兼容行为保留，不改外部请求 wire shape。
7. 工单新分析与已保存分析映射均直接使用 Settings 的有效置信阈值。0.0、0.2、0.7、1.0 及边界相等场景均测试；不改默认值、不改危险工单和未知分类规则。

## 审查结论与完成定义

业务、技术、安全、测试、运维与岗位证据六个视角逐项自查；跨小区复杂授权已移出，画像/排序不引入未证实模型，明确保留人工责任与正常自动流程。

批次 A 契约已具体，可用本地纯模拟测试证明，不涉及权限扩张或数据迁移。其余条目是必须保留的后续任务，不是已实施功能；详细设计与独立实验前提仍需逐项满足。运行/GPU、性能、真实模型、真实页面与生产验收不由本批放行。

关闭缺陷须有变更前失败、变更后通过、相关回归及代码差异。方案自查不等于独立复审，单测不等于真实模型效果。
