# 主管只读队列助手

## 目标与范围

复用现有主管队列和诊断能力，回答“当前待派/升级队列中，哪些工单需要先核实，依据是什么”。这是单 Agent 的受限工具循环；不替换固定诊断，不改变派单或工单状态，不引入 LangChain、依赖升级、数据库迁移或新任务队列。

模型从白名单选择 queue、diagnose、finish。queue 读取固定小区当前队列的一页（最多 5 条）；diagnose 仅接受本次队列出现的 ID 和版本；finish 只能选择已经诊断的工单和存在的事实代码。最终说明由服务端事实和建议组成，不能由模型编造事实或引用。模型排序只供人工参考，不是自动派单优先级。

## 权限与数据

用户、租户和小区由认证上下文与请求固定，模型不能修改。模型调用前、每次工具读取和最终返回前重新鉴权。每次 SQL 查询使用独立短会话，结束后关闭，不跨模型请求保持事务。版本或权限变化时拒绝返回旧结论。模型仅看到 ID、状态、优先级、超时与固定诊断事实，不发送住户描述、电话、房号或员工画像。

## 预算、终止与失败

单次最多 7 次规划调用、1 次队列工具、3 次不同工单诊断；检查点时间预算默认 30 秒，每次 Provider 的连接/读写等待超时不大于剩余预算。工具与模型返回后再次检查预算，迟到结果不返回。同步数据库驱动及持续分段返回的 HTTP 响应均无法被该检查点强制中断；这不是总墙钟硬截止，不能用于承诺严格实时 SLA。禁止任意工具名、额外参数、SQL、URL、文件访问及重复工具循环。

开发 Provider 明示 deterministic_stub；真实模型须通过已有 Qwen Provider。失败返回稳定 AGENT 错误码与空结果，原固定诊断仍可使用。结果分开记录 planner_steps 和 model_calls，后者为 Provider 尝试次数、不是成功响应数；桩为零。结果包括 request_id、无正文的步骤轨迹、来源和页范围；不输出模型思维链。

## 集成与验收

新增独立 Service / Provider / Schema 和主管 POST 接口。开关默认关闭，不修改现有运行配置；需要进入实际运行窗口时单独核对授权、资源和预算。先完成纯单元及接口失败路径，再做隔离数据库和真实模型验收，最后决定页面入口是否达到可发布条件。

小程序通过重新鉴权的 capabilities 查询决定是否展示入口；后端未启用时隐藏按钮。结果仅在小区、队列代次和工单版本仍匹配时显示。切换、刷新、隐藏、派单、改派、异常决定、撤销或重分析均使旧建议失效，网络失败也不恢复旧结果。演练模式明确标注未调用真实模型。

必须覆盖：模型根据不同工具结果选择下一步；住户/跨小区拒绝；中途撤权；工单变更；伪造 ID/事实；重复循环；非法 JSON；Provider 失败；超时/步数耗尽；空队列；结果不含个人信息。测试桩通过不等于真实模型 Agent 效果。
