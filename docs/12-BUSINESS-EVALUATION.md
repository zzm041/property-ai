# 业务效果评测

本说明约定工单理解评测的统计口径，不改变派单、权限或人工接管政策。

## 证据分组

真实模型运行、保存输出回放、合成桩测试分别汇总，不能混合计算准确率。样本按开发、回归、预留分组；曾被用于调整提示词、校验词表或规则的样本转为回归集，不再作为新预留集。

预留样本需在运行前固定内容、预期行为和数据指纹。标注应覆盖可确定事实、不能推断的事实、应澄清内容、风险、职责及用户限制；标注者和复核状态必须记录。由实现者或同一助手撰写的样本，不称为独立人工标注。没有模型输出的样本也要保留在总分母中。

现有 `reports/delivery-closeout-20261103/work-order-validator-heldout.json` 的两条样本已用于修复，后续只能算回归样本。原真实运行 1/2 通过与修复后的保存输出回放 2/2 分开保留，不合并声称模型准确率提升至 100%。

## 指标

| 指标 | 分母与含义 |
| --- | --- |
| 运行覆盖率 | 有运行记录样本数 / 全部样本数；记录缺失不能被静默跳过 |
| 决策一致率 | 与预期处理方式一致的样本数 / 全部样本数；同时展示有有效输出的分母 |
| 过度拒绝率 | 应形成可用结构化信息、实际转澄清或人工的样本 / 所有预期可结构化样本 |
| 错误放行率 | 应澄清或人工、实际判为可用结构化信息的样本 / 所有预期应澄清或人工样本 |
| 字段一致率 | 严格等值检查通过的字段 / 明确标注的字段；缺失字段算不一致，不当作自然语言语义准确率 |
| 人工修改率 | 人工实际修改字段数 / 人工实际检查字段数；未观察时为 null，不能填 0 |
| 处理耗时 | 分别展示模型响应时间和人工处理时间；回放耗时不得冒充模型推理耗时 |
| 人工收益 | 只有同等任务的人工基线与辅助处理配对观测才能比较，不能用模型响应耗时推算人工节省时间 |

决策标签 `READY / CLARIFY / MANUAL` 仅描述结构化信息是否可用、需澄清或转人工，不代表已经派单，不绕过住户联系要求、权限或员工资格。

## 离线汇总工具

`scripts/evaluation/business_metrics.py` 仅读取本地 JSON，不启动服务、不调用模型、不读取数据库。数据集包含 `cohort`、`label_origin`、`review_status` 和 `cases`；每条样本有唯一 `id`、`expected_decision`，可选 `expected_fields`。这些预期应来自评测标注，不能从被评估的输出自动生成。

运行文件包含 `kind`（`real_model / saved_output_replay / synthetic`）、绑定的数据集指纹 `dataset_sha256`、唯一案例记录 `cases`、模型/提示词/代码版本元数据。案例记录包含 `id`、`status`（`ok / provider_error`）、成功时的 `decision`，可选 `fields`、`latency_seconds`、实际人工观测 `human_review`（`checked_fields / changed_fields`）。

工具拒绝未知或重复 ID、指纹不符、非法数值和回放伪装的新模型调用。空分母输出 null。调用次数与成功输出数不等价；调用统计由运行器记录，不从样本通过数推断。

```powershell
./.venv/Scripts/python.exe scripts/evaluation/business_metrics.py --dataset <dataset.json> --run <run.json> --out <new-summary.json>
./.venv/Scripts/python.exe -m pytest scripts/evaluation/tests -q
```

汇总只能验证输入记录的自洽性，不能证明标注独立性或运行日志真实性；发布结论仍须核对原始输入、输出、指纹、标注与执行轨迹。输出文件必须新建，不覆盖旧结果。

## 后续真实评测

1. 收集未参与调试的表达，覆盖口语、省略、否定、历史与当前状态、主体混淆、多问题、联系限制、危险信息和无效请求；文字、图片和语音分别报告。
2. 独立复核标注，运行前冻结样本与预期；不把这一步的准备完成写成模型通过。
3. 在具名自托管模型窗口中执行，记录模型、提示词、代码、预算、超时和失败；不重试到通过后删除首次失败。
4. 分析误拒与错误放行，再决定哪些语义约束交给模型、哪些确定性边界继续由规则负责。
5. 在实际使用观察中另行收集人工修改与配对耗时。没有观察数据时保留缺口，不估造收益。
