# 面试展示与交付准备

本项目用于 AI 应用开发求职。完成标准是可核查的源码、可理解的业务与工程说明、可受邀操作的真实 AI 演示，以及我们这边完整且可部署的交付包。甲方真实安装、商业上线、持续运营和签字验收不属于本次收尾条件。

## 面试官的访问路线

1. 查看 [作品首页源码](showcase/index.html) 或仓库 README，了解业务问题、AI 职责、规则派单与验证范围。首页为纯静态文件，可本地打开，也可发布到静态托管；当前没有已发布的网址。
2. 持有人在面试现场提供受邀体验地址和一次性口令。面试官通过现有浏览器入口提交一条合成报修，查看真实分析与实际派单状态；完整角色流程使用微信原生小程序展示。
3. 结合 [架构与部署](09-DEPLOYMENT.md)、[AI 与派单规则](05-AI-DISPATCH-SPEC.md) 和 [验证状态](14-DELIVERY-STATUS.md) 讨论技术取舍。源码公开已获持有人授权，外部是否可见仍以实际仓库设置为准；主页链接不代表远程 AI 入口已经开启。

作品首页不发起任何模型/业务请求，不包含邀请口令、用户资料、模型密钥或自动开放入口的脚本。页面上的示意场景明确标为设计说明；不能将其当作实时输出。

## 一次现场演示

建议控制在约五分钟讲解，再按面试官兴趣深入；这是讲解安排，不是模型响应时间承诺。

- **业务问题：**住户表达形式不统一，人工需要反复整理信息；派单还需要员工范围、在岗、职责和容量约束。
- **真实操作：**面试官选择合成文字报修，提交后先看到已创建工单，再观察实际分析状态。普通维修、需要澄清或人工跟进以实际结果为准，不预设必须成功派单。
- **结果解释：**指出哪些信息由模型提取、哪些校验和选择由业务服务完成。模型不得直接指定员工；不能用模型置信度充当客观准确率。
- **处理闭环：**使用已有小程序展示员工处理、独立“无法处理”页面与住户回执。浏览器适配器目前不提供完整的员工/主管业务控制台，不把小程序能力说成网页已全部实现。
- **工程追问：**解释为什么工单保存不依赖模型成功，如何防重复提交、处理任务失败、控制跨租户访问，以及如何停止本场资源使用。

同一窗口不通过重复提交掩盖模型异常。访问额度耗尽、窗口到期、网络中断、模型不可用均按实际状态说明。面试官需要再次体验时由持有人决定新窗口，不允许远端自行重置额度。

## 真实证据与备用展示

历史真实证据与当前现场输出分别标记。已有本地 AI 分析/自动派单和手机确认，以及五类自托管接口各一条真实合成输入证据；详见验证状态文档。它们不能推导出全量准确率、响应时间保证、实际节省人力或真实客户收益。

当前尚无整理完成的可公开演示录像，不放空的视频链接或使用模拟画面充当真实推理。后续在一次已批准的真实演示中记录关键流程，去除身份、口令、主机信息后再作为备用材料；不为了录像重复已有专项评测。现场故障时可以打开源码、架构与已明确标注的历史证据，不能把历史输出伪装成新请求结果。

项目采用 AI 辅助开发。简历与现场陈述应区分本人需求判断、实际掌握的设计/调试/验证工作和 AI 辅助代码生成，不把整个仓库的实现量直接等同个人独立编码量。个人职责的最终表述由求职者按实际经历确认，不在展示材料中编造任职、团队、客户或上线收益。

## 收尾边界

**面试可用：**外部访问权限明确，真实受邀入口一次端到端操作与结束关闭核对通过，现场路线和备用材料可用。源码模拟检查不替代这一次实际联通确认。

**交付准备完成：**我们这边提供净源码/版本清单、固定依赖与模型来源、私密配置模板、数据库/存储初始化、启动/停机/备份恢复手册，以及与最终包对应的自有隔离环境安装验证。甲方只需获得明确的部署条件和操作文档；不要求实际甲方出场或签字，也不声称其环境已经验证。

GitHub 用于源码和作品说明；静态作品页可发布到 GitHub Pages 或 Hugging Face Static Space。真实交互继续复用现有受邀入口，不为求职展示迁移整套系统或更换已验证模型。公开仓库/网站、开启远程入口、启动新模型窗口仍分别遵循已约定的操作授权。
